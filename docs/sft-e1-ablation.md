# SFT-e1 与预算/候选记忆消融

> **后续结果**：三轮 24,576-token SFT 已完成，最终选择 e3（19/40）；e3 budget-only 保留全部成功并减少 25.15% 输入 token。见 [`sft-checkpoint-selection.md`](sft-checkpoint-selection.md)。

本页记录已冻结的 Qwen3.5-2B SFT-e1 检查点及其 40-task 配对开发评测，目的是决定进入 GRPO 的配置。原始轨迹、汇总和配对统计位于 `outputs/sft-e1/`；大文件不进入 Git。

## SFT-e1 训练

单张 RTX 4090 24GB 使用 QLoRA、Liger、BF16、12,288 token 最大长度和梯度累积 8 完成 1 个 epoch：

- 训练集 792/800 条保留，验证集 198/200 条保留；
- 99 个优化器 step，训练约 76 分钟；
- train loss 0.3971，eval loss 0.3566；
- 峰值显存 10.5 GiB；
- LoRA adapter 约 277 MiB，合并后的 BF16 模型约 4.2 GiB。

训练日志显示的 `eval_loss=N/A` 是训练脚本最终摘要未回填评估字段；Trainer 实际输出的 eval loss 为 0.3566。

## SFT 是否有效

在同一批 40 个开发任务上，原始 Qwen3.5-2B baseline 为 0/40 严格成功；SFT-e1 baseline 为 18/40（45%）。完成率从 10/40 提升到 38/40，Guard 拒绝从 155 降到 13，invalid-action-limit 终止从 28 降到 0。

这说明 SFT 学到了可执行的工具调用、规格选择和购买流程。这个对比足以证明当前项目的 SFT 阶段有效，但 40 条仍是开发数据，不能替代 Final-200 Clean。

## 四臂配对消融

所有 SFT-e1 arm 使用同一模型、同一 40 个任务、temperature 0、24,576 context 和最多 35 个环境 step。

| Arm | Candidate memory | 100k 硬上限 | 严格成功 | Done | 输入 token | 平均 step | Guard 拒绝 |
| --- | --- | --- | ---: | ---: | ---: | ---: | ---: |
| baseline | 关闭 | 关闭 | 18/40 | 95.0% | 2,208,741 | 8.675 | 13 |
| budget-only | 关闭 | 开启 | 18/40 | 92.5% | 1,573,200 | 7.825 | 10 |
| memory-only | 开启 | 关闭 | 14/40 | 97.5% | 2,042,856 | 7.725 | 2 |
| memory-v4 | 开启 | 开启 | 14/40 | 92.5% | 1,609,589 | 7.075 | 2 |

Budget-only 与 baseline 的严格成功 task ID 完全一致，同时总输入 token 减少 635,541（-28.77%）。三条失败轨迹触发 100k 硬上限，所以这个节省量主要来自提前截断高成本失败，不能解释成所有轨迹都等比例变短。

Candidate Memory 相对 baseline 新增 task 1220，但丢失 task 302、2898、13368、13399、14141，净减少 4 个严格成功（-10 个百分点）。memory-only 与 memory-v4 的得失 task 完全一致，说明退化来自记忆注入，而不是 100k 上限。

## Candidate Memory 退化诊断

当前 1,024-token 视图按“已核验、最近看到、搜索排名、字段数量”排序，没有根据用户约束计算候选匹配度。它通常只能容纳 4–5 个候选，并重复搜索结果里已有的信息。

退化覆盖三类行为：

- **买错商品**：task 302 从正确柴犬粮切换到 15kg 通用犬粮；task 13399 从满足 80TB/脱机克隆要求的目标底座切换到搜索 rank 1 的普通双盘底座；task 14141 从带可视功能、约 357 元的目标洁牙器切换到更便宜但不满足完整条件的候选。
- **商品正确但规格错误**：task 2898 打开正确跑鞋后选择了错误颜色；task 13368 打开正确调料后把“10 汤包 + 10 干包”选成“10 汤包 + 20 干包”。
- **一次正向纠错**：task 1220 中记忆让模型从近似杀菌剂切换到完全匹配的搜索 rank 1 商品。

因此不能只把问题归因于候选排序。即使目标商品排第一，额外系统提示也会扰动 SFT 已学到的规格选择行为；而当目标搜索排名较低时，固定 token 预算又可能把它从记忆视图中挤掉。

## 下一阶段决定

GRPO 主实验使用 `grpo_budget_only_v1`：关闭 Candidate Memory，启用 60,000 token 之后的封顶软成本。`grpo_budget_memory_v1` 保留为负向消融，不作为当前推荐训练配置。

评测中的 100k 是硬停止条件；GRPO 中的是软奖励塑形：

```text
min(max(cumulative_input_tokens - 60000, 0) / 1000 * 0.001, 0.1)
```

二者都针对累计输入成本，但机制不同。40-task 的 budget-only 结果支持继续研究预算约束，不能直接证明软惩罚训练一定提升成功率。

这些 40 条任务已经用于 SFT-e1 配置决策，今后属于开发集。若重新设计 Candidate Memory，不能在同一 40 条上反复调参后仍称为未见评测。GRPO 配置冻结后，只有用户明确要求时才执行训练与 Final-200 Clean。
